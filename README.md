##4.programming principles

###4.1KISS-Keep It Simple,stupid

KISS means keeping code as simple as possible.simple code is easier to understand,test,and maintain.
In my code,I used simple functions for calculations and other tasks.For example,the 'calculate_total()'
function uses a simple calculation instead of unnecessary code.This principle is useful because another developer can understand the purpose of the function quickly.

###4.2DRY-Don't repeat yourself

DRY means avoiding unnecessary repetition in code.In my requisition system,methods and functions are used to perform tasks rather than repeating the same code in many places.My 'calculate_discount()' example also shows how a calculation can be placed in a reusable function.Using DRY can make a program easier to maintain because a change can be made in one place.

###4.3SRP - single Responsibility priciple

SRP means that a class or function should have one main responsibility.In my requisition system ,the 'Requisition'class is responsible for storing and managing information about a requisition.
keeping responsibilities separate makes the code easier to understand and maintain.

##34.4Separation of concerns

Separation of concerns means separating different parts of a program according to their tasks.For example,displaying information can be handled separately from calculations and data processing.
I used this idea in my programs by using separate methods for different tasks.This makes the program easier to change and yroubleshoot.

##34.5 YAGNI-You aren't gonna need it

YAGNI means that developers should not add features that are not currently needed.In my requisition system, i focused on the features required for the system instead of adding unnecessary functionality.
This can reduce the amount of code and make the program easier to manage.

###4.6OCP-open/closed principle

OCP means that software should be open to extension but should not require unnecessary change to existing working code.In my requisition system,the approval process is handled separately,this means that additional approval rules could be added in the future without changing the whole program.
This priciple can make software easier to extend.
